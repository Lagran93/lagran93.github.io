# 配置发布

## 它解决什么问题

配置发布把域名、规则、WAF 与高级设置的变更变成**可审批、可灰度、可回滚的版本**，而不是保存即生效。适合多环境、多团队、需要变更审计的场景。

菜单：`加速服务 → 配置发布`，**仅管理员可见**（需 `config:read` / `config:write` 模块权限）。

## 两种工作模式

| 模式 | 判定 | 修改后 |
| --- | --- | --- |
| 直接生效 | `domains.published_version_id` 为 `NULL` | Edge 15 秒内拉取到新配置 |
| 发布模式 | `published_version_id` 已有值 | 只产生新版本，**不**影响线上 |

判断某个域名当前处于哪种模式：

```sql
SELECT name, published_version_id FROM domains WHERE name = 'cdn.example.com';
```

- `NULL`：直接生效
- UUID：发布模式，Edge 读取该版本快照

域名第一次成功发布后进入发布模式，此后不会自动退出。域名设置弹窗在发布模式下会显示警告：“保存后不会立即下发，请创建并审批发布单”。

## 页面结构

```text
配置发布
├─ 配置版本：每次保存生成一条，含字段级 Diff
└─ 发布单：选择域名与版本，审批、灰度、发布、回滚
```

## 完整流程

```text
1. 修改域名 / 规则 / WAF / 高级设置（每步都会生成 config_version）
2. 配置发布 → 配置版本：确认目标版本与 Diff
3. 新建发布单：选择域名与对应版本
4. 可选：勾选灰度节点（不选=全量）
5. 提交审批
6. 管理员审批（approve）
7. 发布（publish）
8. 目标节点应用并回执 apply-report
9. 全部成功后写入 published_version_id → published
```

状态机：

```text
pending_approval → approved → publishing → published
                        │            │
                        └────────────┴──→ rollback（失败/超时/手动）
```

## 灰度

- 不选节点：立即对所有在线节点生效
- 选节点：只有目标节点切换到新版本，其他节点继续使用旧版本
- 目标节点在 **120 秒**内未回执 `apply-report`，或有节点回执失败 → 发布单自动回滚，旧配置继续生效
- 回执需要一个能从 Control 访问的 `agent_url`；节点离线时不要用灰度，先直接发布或排除该节点

## 回滚

| 场景 | 操作 |
| --- | --- |
| 单个域名配置错误 | 配置版本 → 选择上一个版本 → 回滚 |
| 发布单失败 | 系统自动回滚，无需人工 |
| 已发布但发现问题 | 发布单 → 回滚当前发布 |

回滚同样是“发布一个新版本”，因此可审计、可追溯。

## 与其它功能的关系

| 功能 | 是否受发布模式约束 |
| --- | --- |
| 域名/源站/高级设置 | 是 |
| 缓存规则 | 是 |
| WAF 设置、规则、IP/Geo 名单 | 是 |
| 证书 | 否（即时下发） |
| 刷新、预热 | 否（即时执行） |
| 节点启停、升级 | 否 |

## 常见问题

| 现象 | 原因 |
| --- | --- |
| 规则测试器命中但线上不变 | 域名已启用发布，未发布新版本 |
| 保存后边缘没变化 | 同上；或 Edge 尚未到 15 秒同步周期 |
| “发布”按钮不可用 | 未审批；已有进行中的发布单；当前账号无 `config:write` |
| 发布失败并自动回滚 | 灰度节点回执失败或 120 秒超时；检查节点在线状态与 `agent_url` |
| 回滚后仍是新配置 | 节点未应用；刷新页面确认 `published_version_id`；必要时在节点列表查看版本 |
| 找不到配置发布菜单 | 非管理员，或用户组缺少 `config:read` |
